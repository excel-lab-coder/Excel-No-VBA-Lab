Excelが遅い見落としやすい原因 ― メモリスワップと数式設計の関係

本稿の信頼性について

公式資料実務経験設計上の目安

本稿は、低スペック環境での実務経験、Microsoft公式ドキュメント、Excel MVPの検証記事、コミュニティの議論を基に構成しています。ある程度の実機テストを行ったうえで作成していますが、すべてのパターンを網羅的に検証したわけではありません。本稿の内容は「なぜ遅くなるのか」「どう設計すれば改善できるのか」の考え方を説明するものであり、環境やバージョン、データ構成によって結果が異なる場合があります。

読者ご自身の環境で実際に計測し、結果を確かめたうえで適用されることを推奨します。もし本稿と異なる結果が得られた場合は、そちらが正しい可能性があります。

1. 「関数を変えても遅いまま」の正体

Excelの高速化というと、「VLOOKUPをINDEX+MATCHに変えろ」「SUMPRODUCTをCOUNTIFSに変えろ」といったアドバイスをよく見かけます。しかし、これらの関数を置き換えても体感速度がまったく変わらないケースが少なくありません。

このとき確認したい原因の一つが、メモリ不足によるスワップ（ページング）です。メモリに乗り切らないデータがディスクに退避されると、関数の速度差よりスワップの影響が大きくなる場合があります。

本稿では、この「スワップ」を軸に、Excelが遅くなるメカニズムと、数式設計レベルでの対策の考え方を解説します。

2. RAM・SSD・HDDの速度差 ― 大きな性能差

まず、Excelの計算がどこで行われるかを理解する必要があります。通常、セルのデータや数式はRAM（メインメモリ）に展開され、CPUが処理します。RAMは極めて高速ですが、容量に限りがあります。

物理メモリが不足すると、Windowsは使用頻度の低いデータをディスク上の「ページファイル」に退避します。これがスワップです。再びそのデータが必要になると、ディスクからRAMに読み戻す「ページイン」が発生します。この読み戻しの速度がボトルネックになります。

メモリ不足でページファイルへの読み書きが増えると、ストレージの種類や空き容量、同時に動作するアプリによっては再計算が大幅に遅くなり、応答停止のように見えることがあります。SSDではHDDより影響が小さくなる傾向がありますが、メモリ不足そのものの解消にはなりません。

3. 32ビットExcelのメモリ制限と「4GBのPC」の現実

32ビット版Excelは、Excel 2013以降のLAA（Large Address Aware）対応により、64ビットWindows上で最大4GBの仮想メモリを使用できます。それ以前のバージョンでは上限は2GBでした。

ただし、仮想アドレス空間の上限と、実際に空いている物理メモリは別です。Windows、常駐ソフト、アドイン、同時に開いているブックの使用量はPCごとに異なります。

物理メモリが少ない環境ではページングが起こりやすくなりますが、4GBのPCだから必ず発生する、または特定の数式だけで何秒遅くなるとは決められません。タスクマネージャーでメモリ使用量とディスク使用率を確認してください。

4. VLOOKUP vs INDEX+MATCH ― 参照範囲の指定方法

数式上の比較「VLOOKUPよりINDEX+MATCHが速い」と固定的に判断することはできません。Microsoftの性能ガイドでは、掲載条件においてVLOOKUPはINDEX+MATCHよりわずかに高速でメモリ使用量も少ない一方、MATCH結果を複数のINDEXで再利用できる柔軟性が説明されています。

4-1. 数式で指定する参照範囲の比較

VLOOKUPは検索列から戻り列までを連続した table_array として指定します。INDEX+MATCHは検索列と戻り列を個別に指定できます。これは数式上の参照範囲の違いであり、そのセル数をそのまま実メモリ使用量へ換算することはできません。

例：B列で検索し、F列の値を返す場合（5,000行）

=VLOOKUP(A1, B1:F5000, 5, FALSE)

→ 数式上は、B〜F列の連続範囲を table_array に指定

=INDEX(F1:F5000, MATCH(A1, B1:B5000, 0))

→ 数式上は、検索列Bと戻り列Fを個別に指定

数式で指定する範囲の違い（5,000行の例）
取得列VLOOKUPの指定INDEX+MATCHの指定読み方
5列目B:F の連続範囲B列とF列実メモリ比ではない
10列目B:K の連続範囲B列とK列実メモリ比ではない
20列目B:U の連続範囲B列とU列実メモリ比ではない

⚠ 実メモリ量はこの表から計算できません：Excelが参照範囲を内部でどのように保持・評価するかの詳細は公開されていません。関数名だけでメモリ順位やスワップ発生を判断せず、参照範囲、数式数、Excelの版を揃えて実測してください。

4-2. XLOOKUPの参照指定

XLOOKUPも検索配列と戻り配列を個別に指定できます。ただし、この指定方法だけからVLOOKUPより実メモリが少ないとは断定できません。保守性、対応バージョン、再計算時間を合わせて比較します。

=XLOOKUP(A1, B1:B5000, F1:F5000)

→ 数式上は検索配列B列と戻り配列F列を個別に指定

5. Excelの内部キャッシュ ― 同一範囲の使い回し

5-1. 公式に説明されている対象

Microsoft公式Microsoft 365 version 1809以降では、未並べ替えデータの完全一致VLOOKUP・HLOOKUP・MATCHについて、検索列の内部キャッシュインデックスを後続の検索で再利用する改善が説明されています。ここからXLOOKUP、INDEX+MATCH、すべてのExcel買い切り版へ同じ条件を一般化はしません。

Microsoftの公式テストでは、5列の同一テーブルに対するVLOOKUP 100行がExcel 2010で37秒 → Excel 2016で12秒に短縮されたと報告されています。

またMicrosoft 365 version 2005以降では、SUMIFS・AVERAGEIFS・COUNTIFS等と単一条件版について、同じ検索範囲を使う後続集計でキャッシュインデックスを再利用する改善が説明されています。

出典：Excel performance and limit improvements - Microsoft Learn

公式資料が示す効果は対象バージョンと対象関数に限られます。実務では、同じマスタを参照する数式の範囲を揃えることを、キャッシュ保証ではなく保守性と比較条件の統一として扱います。

5-2. コピー時に参照範囲をずらさない

相対参照のまま数式をコピーすると、検索対象そのものが行ごとにずれ、結果の誤りや比較条件の不一致につながります。

セルB1: =VLOOKUP(A1, D1:H5000, 5, FALSE) → D1:H5000 セルB2: =VLOOKUP(A2, D2:H5001, 5, FALSE) → D2:H5001（ずれた） → 検索範囲が意図せず変わる

検索対象を固定したい場合は絶対参照にします。

=VLOOKUP(A1, $D$1:$H$5000, 5, FALSE)

→ どのセルにコピーしても参照先は D1:H5000

ドル記号は内部キャッシュを直接指定する機能ではありません。コピー後も同じ検索範囲を保ち、数式の意味を安定させるために使用します。

💡 名前の定義のメリットは保守性

名前の定義の主な利点は可読性と保守性です。範囲変更を一箇所にまとめられますが、名前を付けるだけで速度やメモリ効率が必ず改善するわけではありません。OFFSETなどの揮発性関数を含む名前は再計算への影響も確認します。

6. スワップ環境で効く数式設計の考え方

メモリ不足が確認できた場合はハードウェア増強が有効な候補ですが、企業のPCは情報システム部門が一括管理し、簡単にはメモリ増設やSSD換装ができないのが現実です。ここでは、数式設計レベルでスワップの影響を軽減するための考え方を整理します。

6-1. 参照範囲の最小化 ― 列全体参照の実態

列全体参照（例：B:B）について、「104万行をメモリに展開するから遅い」という説明をよく見かけますが、これは正確ではありません。

Microsoft公式SUMやSUMIFなどは未使用セルを比較的効率よく扱える一方、必要以上の使用セルを含めず、テーブル、限定範囲、動的範囲を使うことが推奨されています。完全一致検索も検索範囲を小さくすることが推奨されています。

一方、配列計算やSUMPRODUCTでは列全体参照の負荷が大きくなる場合があります。したがって、列全体参照を一律に禁止または推奨せず、関数の種類と実データ範囲で判断します。

比較候補： =COUNTIF(A:A, "東京") → 列全体の件数が目的の場合 =COUNTIF($A$2:$A$5000, "東京") → 対象範囲が決まっている場合 =COUNTIF(テーブル1[地域], "東京") → 行追加へ自動追従させる場合 ※ 3式は同じデータ範囲を対象にした状態で、結果と再計算時間を比較する

外部の実測例補足資料：Excel Full Column References and Used Range: Good Idea or Bad Idea? - FastExcel

したがって、列全体参照が直ちに遅くなるわけではありませんが、以下の理由から実データ範囲に絞る方が安全です。

推奨：範囲を明示する理由 1. UsedRangeの肥大化リスクを排除 → 誰かが最終行に書式を設定しただけで全体が遅くなる 2. SUMPRODUCT・配列数式との混在を防止 → 他の人が配列数式に書き換えた瞬間に遅くなる 3. 数式の意図を確認しやすい → どの行までが処理対象かをレビューしやすい 4. 比較条件を揃えやすい → 同じ範囲を使う式同士で結果と再計算時間を比較できる

6-2. IF空白判定による処理スキップ

作業列にコピーした数式で、データが空白の行では重い計算を実行しないようIF文で制御できます。

=IF(A1="", "", VLOOKUP(A1, $D$1:$H$5000, 5, FALSE))

Excelのセルコピー数式では、IF関数は条件を満たした時点で残りの引数を評価しません（短絡評価）。A1が空白なら、VLOOKUPはまったく実行されず、空文字が即座に返されます。

空白行で検索式を評価しない構成は、不要な計算を減らす候補になります。ただし、短縮幅はデータ量、依存関係、Excelの版で変わるため、変更前後を計測してください。

6-3. 作業列の配置と参照パターン

作業列を元データの近くへ置くと、数式の追跡や引き継ぎがしやすくなります。ただし、列が近いこと自体でExcelのメモリアクセスが速くなるとは確認できないため、ここでは保守性のための配置として扱います。

読みやすい配置例: A列の入力 → B列で判定 → C列で結果 離れた列を使う場合: 見出し、テーブル名、定義名などで参照目的を明確にする

6-4. 参照範囲を意図どおり固定する

検索対象が同じマスタなら、コピー後も同じ範囲を指すようにします。これは結果を安定させ、比較テストの条件を揃えるための基本です。

意図せず範囲がずれる例: B1: =VLOOKUP(A1, $D$1:$H$5000, 3, FALSE) C1: =VLOOKUP(A1, $D$1:$H$5001, 5, FALSE) ← 5001行で不一致 同じマスタ範囲に揃える例: B1: =VLOOKUP(A1, $D$1:$H$5000, 3, FALSE) C1: =VLOOKUP(A1, $D$1:$H$5000, 5, FALSE) ← 同一範囲

7. 揮発性関数がスワップを誘発する理由

INDIRECT、OFFSET、NOW、TODAY、RANDなどの揮発性関数は、通常の再計算でも関数自体が再評価されます。大量に使うと、変更箇所を絞って計算する「スマート再計算」の効果を得にくくなる場合があります。

メモリが不足している環境では、この再評価と依存先の計算が重なり、待ち時間が増えることがあります。必要な場面だけに限定し、単純な直接参照などで代替できる場合はそちらを検討します。

揮発性を含む例: =SUMPRODUCT((INDIRECT("A1:A"&ROW())="東京")*1) → 入力のたびにブック全体が再計算 非揮発性の代替: =COUNTIF($A$1:$A$5000, "東京") → 依存セルの変更時のみ再計算

8. スピル数式とセルコピー ― スワップ環境での違い

8-1. フル再計算時の速度比較

Microsoft 365 / Excel 2021以降で利用できるスピル（動的配列）数式は、1つの数式から複数行の結果を展開します。セルごとに数式をコピーする方式とは、保存される数式数と依存関係の持ち方が異なりますが、内部の解析回数や関数呼び出し回数を単純に「1対行数」とは換算できません。

スピル vs セルコピー ― 比較時の確認点（1万行の例）
項目スピルセルコピー
数式が入力されるセル起点セル各行
結果の表示配列として展開各セルで表示
再計算範囲配列と依存関係により変化依存関係により変化
ファイルサイズ小さくなる場合がある数式数に応じて増える場合がある
速度Excelの版・関数・データ形状を揃えて実測

ブックを開いた直後や Ctrl+Alt+F9 による強制再計算では、条件によってスピルの方が短時間になる場合があります。

8-2. セル単位変更時の再計算

Excelのスマート再計算は、変更セルと依存関係を基に再計算対象を決めます。スピル式では配列範囲が一つの数式に依存するため、変更内容によっては広い結果範囲が更新されます。セルコピーでも依存関係が広ければ多数のセルが再計算されます。

したがって「編集時は必ずセルコピー」「フル再計算は必ずスピル」と固定せず、通常再計算と完全再計算を分けて計測します。

8-3. IF空白判定の効き方の違い

空白行を先に除外する、または入力範囲を実データ行までに絞ると、不要な評価を減らせる場合があります。IFの内部処理回数を推測するのではなく、同じ結果になる式で比較してください。

8-4. スピルの範囲制御による最適化（検討しやすい構成）

スピルの入力範囲を実データ行数に近づける方法として、最終行を1セルで算出し、INDEX:INDEX構文で範囲参照を作る手法があります。データ途中に空白がある場合はCOUNTAだけでは最終行にならないため、実データの条件に合わせて調整してください。

ステップ①：最終行の算出（1セルだけ）

=COUNTA(A2:A10000)

→ Z1セルに配置。ヘッダーを除いたデータ行数を返す（例：5,000）

ステップ②：INDEX:INDEX構文で実データ範囲だけを参照してスピル

=VLOOKUP(INDEX(A2:A10000,1):INDEX(A2:A10000,Z1), $D$1:$H$5000, 2, FALSE)

→ B2セルに配置。Z1が5000なら、数式上の入力範囲はA2:A5001になる。

=VLOOKUP(INDEX(A2:A10000,1):INDEX(A2:A10000,Z1), $D$1:$H$5000, 5, FALSE)

→ C2セルに配置。同じINDEX:INDEX範囲で別の列番号を返す。

=INDEX($H$1:$H$5000, MATCH(INDEX(A2:A10000,1):INDEX(A2:A10000,Z1), $D$1:$D$5000, 0))

→ INDEX+MATCH版。検索列と戻り列を個別に指定する。

INDEX:INDEX構文のポイント

INDEX(A2:A10000, 1) → A2（範囲の先頭セル） INDEX(A2:A10000, Z1) → A5001（Z1=5000番目のセル） この2つをコロンでつなぐと： A2:A5001 という「セル範囲参照」が生成される ポイント： ・INDIRECTのような揮発性関数ではない ・Z1の値を使って数式上の範囲参照を作れる ・途中空白やエラーを含むデータでは、最終行の求め方を調整する

💡 なぜINDIRECTやOFFSETではなくINDEX:INDEXか

INDIRECTやOFFSETは揮発性関数で、通常の再計算でも再評価されます。INDEXを使った範囲参照は非揮発性なので、動的範囲を作る候補になります。ただし、依存セルの変更による再計算は発生します。

なぜこの構成で負荷を抑えやすいのか

比較する3案： パターンA: セルコピー + IF空白判定 パターンB: 最大行までを入力にしたスピル パターンC: INDEX:INDEXで入力範囲を絞ったスピル 確認項目: ・結果件数とエラー件数が一致するか ・通常再計算と完全再計算の時間 ・ファイルサイズと編集時の応答 ・途中空白を含むデータでも範囲が正しいか

パターンCの利点は、最終行の判定をセルに分離して複数の数式で再利用でき、数式上の入力範囲を管理しやすい点です。どの案が速いかは、関数、データ形状、Excelの版で変わります。

⚠ 注意：INDEX:INDEX構文の内部メモリ処理は公開されていません。「メモリ展開が何セル分」とは換算せず、数式上の範囲を限定する設計例として使用してください。

補足：TAKE関数を使う書き方（Microsoft 365 / Excel 2024以降）

=VLOOKUP(TAKE(A2:A10000, Z1), $D$1:$H$5000, 2, FALSE)

→ TAKE関数は配列の先頭からZ1行分を返す。INDEX:INDEXとは式の意味が異なるため、結果と再計算時間を比較して選ぶ。

9. Excelバージョンによる計算エンジンの改善

同じPCでもExcelのバージョンによって計算時間が変わる場合があります。これは関数単体の改善だけでなく、メモリ管理や計算処理の改善も関係します。

10. 原因別の確認候補 ― 何から手をつけるべきか

Excelの高速化は、まずボトルネックを確認してから対策を選びます。メモリ不足が確認できた場合は、関数の置き換えよりハードウェア環境の見直しが有効なことがあります。

12. 補足：32ビットと64ビットで異なるメモリ上限

32ビットExcelと64ビットExcelでは利用できる仮想アドレス空間が異なるため、大規模ブックでの余裕に差が出ます。

32ビット環境では、メモリが限られるためスワップ回避が最優先です。参照範囲を絞り、作業列を最小限にし、不要な列を削除してメモリ使用量を抑える設計が有効です。

64ビット環境でも、広すぎる参照範囲や重複計算が軽くなるわけではありません。作業列で中間結果を再利用する方法とスピルで一括計算する方法を、実際のブックで比較します。

ビット数だけで設計を決めず、メモリ使用量と再計算時間を確認することが基本です。

⚠ 注意：32ビットと64ビットの設計差については、考え方としての説明であり、両環境での網羅的なベンチマークテストは実施していません。実際の効果はデータの規模・数式の複雑さ・PC構成により異なります。

13. まとめ

Excelの遅さには、数式設計、参照範囲、揮発性関数、メモリ不足など複数の原因があります。本記事では、その中でも見落とされやすいメモリスワップを中心に説明しました。

まず参照範囲と重複計算を見直し、同時にメモリ・ディスク使用率を確認します。メモリ不足が確認できた場合は、メモリ増設、SSD、64ビット版Excelなどを候補にします。

スピル数式を使う場合は、INDEX:INDEXなどで入力範囲を管理する案も比較できます。内部処理回数やメモリ量は断定せず、通常再計算・完全再計算・編集時の応答を確認します。

VLOOKUPをINDEX+MATCHへ変える前に、タスクマネージャーでメモリ使用量、ディスク使用率、ページングの兆候を確認してください。使用率の数字だけで原因を決めず、数式変更前後の再計算時間と合わせて判断します。
