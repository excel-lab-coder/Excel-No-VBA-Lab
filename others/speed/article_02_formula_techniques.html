数式の速度UPテクニック集：テーブル・LET・セル参照コスト・FILTER・スピル検索・事前IF・最終行カウント

この記事の位置づけ

  • 記事タイプ：設計事例・比較手順
  • 先に確認：数式変更前後で結果件数・エラー件数が一致すること
  • そのまま使える部分：LET、テーブル、限定範囲などの構文例
  • 実測が必要な部分：秒数、倍率、スピルと個別セルの速度差

前回の記事「検索関数の速度と参照範囲」では、VLOOKUP・INDEX+MATCH・XLOOKUPの関数間の速度差を掘り下げました。 今回はそこからさらに一歩進んで、「関数の選び方」ではなく「数式の書き方・構造の工夫」で速度を上げるテクニックを集中的に解説します。

テーブル参照、LET関数による中間結果の再利用、作業セル vs セル内再計算のコスト比較、FILTER関数による一括抽出、スピル検索によるファイルサイズ圧縮、 そして事前IF空白チェックと最終行カウントによるスピル最適化まで、 数式を大きく変えずに負荷を見直す方法と、数式の構造自体を見直す方法の両面を扱います。

速度の数値について：
計算速度はデータ量やブック構成によって変わります。掲載する秒数や倍率は、参照元または例示条件での結果です。重い場合は、実際のブックのコピーで変更前後を比較してください。
🔴 この記事の前提：完全一致検索での話です
速度比較はすべて完全一致検索（VLOOKUP の FALSE / XLOOKUP のデフォルト）を前提にしています。 バイナリ検索（ソート済みデータの二分探索）を使える場合は、検索負荷を抑えられることがあります。 バイナリ検索については「検索関数の速度と参照範囲」の【5】〜【7】を参照してください。

【1】テーブル（構造化参照）― 参照範囲を管理しやすくする土台

Excelの「テーブル」機能（Ctrl+T）でデータをテーブル化し、数式で構造化参照（例：テーブル1[社員ID]）を使うだけで、 実データ範囲に追従するため、不要な行まで参照する数式より負荷を抑えやすいことがベンチマークで確認されています。固定範囲との速度差はデータ構成によって変わります。

外部サイトの掲載条件Ablebits.com ベンチマーク（50万行メイン×500行マスタ）
関数範囲指定
A2:A500		列全体参照
A:A		テーブル参照
テーブル1[列名]		テーブル参照の
高速化率
VLOOKUP 6.6秒14.2秒2.3秒範囲指定の約2.9倍速
INDEX+MATCH 8.9秒17.7秒2.6秒範囲指定の約3.4倍速
XLOOKUP 11.2秒24.1秒3.3秒範囲指定の約3.4倍速
テーブル参照を使う3つの実務上の理由

① 対象範囲を明示しやすい：構造化参照はテーブル列を指すため、列全体参照より処理対象を把握しやすくなります。固定範囲との速度差は関数とデータ構成で変わります。

② 参照範囲を揃えやすい：A2:A500 と A2:A501 のような手入力のずれを防ぎやすくなります。これを「キャッシュ共有100%」という内部処理の保証には置き換えません。

③ 行の追加・削除に自動追従する：テーブル行の追加に合わせて参照が拡張されるため、数式の保守がしやすくなります。

❌ 列全体参照
=VLOOKUP(A2, マスタ!A:E, 3, FALSE)

列全体を数式の参照範囲として指定。
関数によって全列参照の扱いが異なるため、限定範囲・テーブル参照と比較する。
✅ テーブル参照
=VLOOKUP(A2, マスタテーブル, 3, FALSE)

テーブル範囲を参照し、行の追加にも自動追従。
主な利点は範囲管理と保守性。
Microsoft公式の考え方全列参照は関数ごとに判断する
SUMやSUMIFなどは未使用セルを比較的効率よく扱える一方、配列計算では全列参照の負荷が大きくなる場合があります。完全一致検索では検索範囲を小さくし、テーブル、限定範囲、動的範囲を使うことが推奨されています。

したがって「全列参照は常に遅い」「標準検索関数なら常にUsedRangeまで」と一般化せず、対象関数と実データで計測してください。
✅ テーブル化は範囲管理の有力候補
データをテーブル化して構造化参照に切り替えることで、 参照したベンチマークでは、列全体参照や通常範囲より短い計算時間になった例があります。 ただし既存の名前定義、外部参照、共有先との互換性を確認してから切り替えてください。

【2】LET関数 ― 同じ計算を1回だけ実行して再利用する

LET関数（Excel 2021以降）は、数式内で変数を定義し、その結果を複数回参照できる関数です。 同じ部分式が数式内に複数回登場する場合、LETで1回だけ計算して使い回すことで、計算コストを削減できます。

LET関数の基本構文
=LET( 変数名1, 計算式1, 変数名2, 計算式2, 最終的な結果の式 )

変数名に計算結果を格納し、以降の式で何度でも参照可能。各変数は1回だけ計算される。

❌ LETなし ― MATCHが2回実行される
=IF(MATCH(A2,D:D,0)>0, INDEX(E:E,MATCH(A2,D:D,0)), "未登録")

MATCH(A2,D:D,0) が2回書かれている → 2回とも独立して計算される。
同じMATCH式を2か所に記述する構成。
✅ LETあり ― MATCHは1回だけ
=LET(pos, MATCH(A2,D:D,0), IF(pos>0, INDEX(E:E,pos), "未登録"))

MATCHの結果を pos に格納し、IF と INDEX の両方で再利用。
MATCH結果を変数として再利用する構成。
LETが特に効果を発揮するケース
✅ SORT / FILTER の結果を複数回使う
SORT/FILTER の計算結果は配列全体のソートやフィルタリングなので重い処理です。 LETで1回だけ実行してCHOOSECOLSで列を取り出せば、同じSORT処理が何度も走ることを防げます。
✅ 複雑な条件式を複数箇所で使う
例えば IF(AND(B2>100, C2="A"), ...) のような条件を数式内の複数箇所で参照する場合、 LETで条件結果をTRUE/FALSEの変数に格納すれば、条件評価が1回で済みます。
✅ 可読性の向上
速度だけでなく、長大なネスト数式が変数名で分解されるため、保守性・デバッグ効率も大幅に向上します。
💡 LET関数自体のオーバーヘッドはほぼゼロ
Reddit（r/excel）やMicrosoft Tech Communityでの検証によると、 LET関数自体が追加するオーバーヘッドは計測不能なレベルです。 「LETで包んだから遅くなる」ということはなく、重複計算を避けた分だけ純粋に速くなると考えてよいでしょう。 ただし、LETの中で定義した変数を1回しか使わない場合は速度改善の意味がないため、 その場合は可読性向上のための利用と割り切ってください。

【3】セル参照コスト vs セル内再計算 ― 「作業セルに保存」が常に最速とは限らない

Microsoft公式ドキュメントでは「重複する計算は作業セル（ヘルパー列）に分離して再利用せよ」と推奨されています。 しかし実際には、セル参照自体にもコストがあるため、データ規模によって最適解が変わります。

🔴 この節で最も伝えたいこと：「セル参照はタダではない」
Excelの計算エンジンは、セルを参照するたびに依存関係の追跡・値の読み取り・型変換などの処理を行います。 数式内で同じ計算を2回実行するコストと、作業セルに結果を保存して参照するコストのどちらが大きいかは、 「計算の重さ」と「データ行数」のバランスで決まります。
ケーススタディ：MATCH結果を作業セルに保存すべきか？

典型的なパターンとして、同じマスタから3列を取得するINDEX+MATCHを考えます。

方法A：作業セルにMATCH結果を保存
H2：=MATCH(A2, マスタ!A:A, 0)
I2：=INDEX(マスタ!B:B, H2)
J2：=INDEX(マスタ!C:C, H2)
K2：=INDEX(マスタ!D:D, H2)

MATCHは1回だけ。INDEXはセル参照（H2）で行番号を取得。
数式4個 × N行 = 4N個の数式
方法B：数式内でMATCHを毎回実行
I2：=INDEX(マスタ!B:B, MATCH(A2, マスタ!A:A, 0))
J2：=INDEX(マスタ!C:C, MATCH(A2, マスタ!A:A, 0))
K2：=INDEX(マスタ!D:D, MATCH(A2, マスタ!A:A, 0))

MATCHが3回実行される。ただし作業セルの参照コストはゼロ。
数式3個 × N行 = 3N個の数式

⚡ なぜ逆転が起こるのか
セル参照のコストはデータ規模に依存しない「固定コスト」です（依存関係の解決・値の読み取りは一定時間）。 一方、MATCH関数の計算コストはマスタの行数に比例する「変動コスト」です。

マスタが小さいとき → MATCHの計算コストは小さいので、3回実行してもセル参照1回分のコストと大差ない。むしろ作業セルの参照・依存関係追跡のオーバーヘッドが目立つ。
マスタが大きいとき → MATCHの1回あたりの計算コストが大きくなるため、3回実行を1回に減らす効果が出やすい。
✅ 実務での判断基準
・大きなマスタで同じMATCH結果を複数回使う → 作業セルに保存する案を比較
・小規模で使い回しが少ない → セル内で計算する案も含めて可読性を優先
・LET関数が使える環境（2021以降）なら → LETで変数化する方法も候補。作業セルを増やさず、重複計算をまとめられる

LETは同じ部分式を数式内で再利用しやすくしますが、ブック全体の再計算を防ぐ機能ではありません。結果一致と再計算時間で選んでください。
Microsoft公式ドキュメントの推奨：「中間結果を行・列に分離せよ」

Microsoft公式のパフォーマンスガイド（「Excel performance: Improving calculation performance」）では、 「重複する計算を作業セルに分離して1回だけ計算し、他の数式で参照する」ことが第一のルールとして明記されています。

小規模な式では速度差を体感しにくい場合もあります。公式資料の方針を基本にしつつ、作業列の保守性と実測結果を確認してください。

📝 公式ドキュメントの例：期首からの累計SUM
B1=SUM($A$1:$A1) を下へコピーする方式は、行が下がるほど参照セルが増えます。 C1=A1, C2=C1+A2 のように前行の結果を再利用する方式は、各行の計算を小さくできます。
これは累計計算の例であり、すべての数式が同じ割合で短縮されるわけではありません。

【4】FILTER関数で一括抽出 ― 同じ条件のVLOOKUPを何百行もコピーしない

FILTER関数（Excel 2021以降）は、条件に一致するすべての行をまとめて一括抽出する関数です。 「特定の部署の社員一覧を取得する」「特定の月の売上データを抜き出す」といった用途では、 VLOOKUPやXLOOKUPを何百行もコピーするよりも、FILTER関数を1つ置くだけで済む場合があります。

VLOOKUPの繰り返し vs FILTER一発 ― 速度とファイルサイズの比較
❌ 従来：同じ条件のXLOOKUPを何百行もコピー
「営業部」の社員を50件取得するために：

B2：=XLOOKUP(条件, ...)（1件目）
B3：=XLOOKUP(条件, ...)（2件目）
︙
B51：=XLOOKUP(条件, ...)（50件目）

50個の独立した数式。 各数式がそれぞれ検索を行う構成。
ファイルに50個分の数式データが保存される。
✅ FILTER関数で1発抽出
=FILTER(マスタ!A:D, マスタ!C:C="営業部", "該当なし")

数式は1個だけ。 条件に合う全行を1つの式からスピルで出力。
ファイルに保存されるのは1個の数式だけ。
⚡ FILTERは用途が合う場合に比較する
FILTERは「条件に合う全行」を返し、VLOOKUPやXLOOKUPは通常「対応する1件」を返します。処理目的が異なるため、速度だけを理由に直接置き換えません。

「同じ条件で複数件を取得する」用途なら、複数の検索式を並べる方法とFILTERを1つ置く方法で、結果・速度・レイアウトを比較できます。
FILTERが不利になるケース

FILTERはあらゆる場面でVLOOKUPより速いわけではありません。以下のケースでは注意が必要です。

⚠ 結果の件数が不定
FILTERの結果はスピルで展開されるため、出力先のセルが空いている必要があります。 結果件数が可変であるため、レイアウトが固定のシートでは使いにくい場合があります。
⚠ 多数のFILTER数式がある場合
異なる条件のFILTER数式を多数置くと、それぞれが参照範囲を評価します。別方式との速度差が小さい場合もあります。
⚠ 1件だけの完全一致検索
「IDで1件だけ引く」用途ではVLOOKUPやXLOOKUPの方が適切です。 FILTERは「条件に一致する全行」を返すため、1件取得にはオーバースペックです。
✅ FILTERの使いどころまとめ
・同じ条件で複数件の結果を取得したい → FILTER が圧倒的に適切
・IDで1件だけ取得したい → XLOOKUP / INDEX+MATCH の方が適切
・複数条件の組み合わせで抽出したい → FILTER + 論理演算（*や+）が柔軟で高速

【5】スピル検索 ― 1個の数式で15,000行分のVLOOKUPを置き換える

Excel 2021以降では、XLOOKUPやVLOOKUPの検索値に配列（複数セルの範囲）を渡すことで、 1個の数式から結果がスピル（自動展開）されます。 これは速度面に加えて、保存する数式数とファイルサイズを減らせる場合があるというメリットがあります。

従来方式 vs スピル検索 ― 15,000行のVLOOKUPで比較
❌ 従来：15,000行に数式をコピー
B1：=XLOOKUP(A1, マスタ!A:A, マスタ!C:C)
B2：=XLOOKUP(A2, マスタ!A:A, マスタ!C:C)
︙
B15000：=XLOOKUP(A15000, マスタ!A:A, マスタ!C:C)

15,000個の独立した数式がファイルに保存される。
数式1つあたり数十バイト × 15,000 = 数百KB〜数MBの数式データ。
✅ スピル検索：1個の数式で全行を処理
B1：=XLOOKUP(A1:A15000, マスタ!A:A, マスタ!C:C)

数式は1個だけ。結果がB1:B15000にスピルで自動展開。
ファイルに保存されるのは1個の数式データのみ。
ファイルサイズを抑えられる場合がある

Excelのxlsxファイル形式は、内部的にはXMLファイルをZIP圧縮したものです。各セルの数式はXMLとして1つ1つ記録されます。 15,000行の数式をコピーすると、15,000個の <f> タグがXMLに書かれます。

スピル検索では起点となる数式が少なくなるため、数式データを減らせる場合があります。ただし、計算結果、書式、共有文字列などもファイルサイズに影響するため、数式数だけから最終サイズは決まりません。

ファイルサイズの比較イメージ（15,000行のXLOOKUP）
従来方式：15,000個の数式
各行に数式を保存
スピル検索：1個の数式
起点となる数式を1セルに保存
掲載条件での参考値実測例
15,000行の XLOOKUP をコピーしたブック → 約3〜5MB
同じ検索をスピル1数式に置き換えたブック → 約500KB〜1MB
この例ではサイズが小さくなりましたが、同じ割合を保証するものではありません。対象ブックのコピーで保存前後を比較してください。
スピル検索の速度特性 ― 必ずしも「常に高速」ではない

スピル検索は1個の数式で全行を処理しますが、速度面では「常に個別数式より速い」とは限りません。

⚠️ スピル検索の最大の注意点：1セル変更でも全行再計算になる
個別数式なら「A5だけ変更 → B5だけ再計算」ですが、 スピル数式は「A5が変更 → B1:B15000全体が再計算」されます。 検索値が頻繁に変わるシートでは、この再計算範囲の広さが速度低下の原因になることがあります。

逆に、「一度データを入力したらあまり変更しない」シート（月次集計レポートなど）では、 再計算頻度が低いためスピル検索のデメリットはほぼなく、ファイルサイズ削減と保守性のメリットだけが残ります。
✅ スピル検索が特に有効な場面
・データ入力後にあまり変更しない帳票・レポート系のシート
・ファイルサイズを小さくしたい（メール添付・ネットワーク共有）
・数式の保守コストを下げたい（修正は1箇所だけ）
・XLOOKUPのバイナリ検索と組み合わせる場合（元々高速なので再計算コストが小さい）

【6】事前IF空白チェック ― 式の形ごとに効果を確認する

検索値が空白のときにVLOOKUP/XLOOKUPの実行をスキップする「事前IFチェック」は、 個別セル式では不要な検索を省ける場合があります。スピル式では配列全体の依存関係も関わるため、同じ短縮幅になるとは限りません。

個別セル数式（非スピル）：✅ 負荷を抑えやすい

各セルに入力してコピーする従来方式では、空白行の計算を省けるため、事前IFで負荷を抑えられる場合があります。

❌ IFなし ― 空白行でもVLOOKUPが走る
=VLOOKUP(A2, マスタ!D:E, 2, FALSE)

A2が空白でもVLOOKUPを評価し、
結果として#N/Aエラーまたは意図しない値を返す。
空白行にも検索式が入っている構成。
✅ 事前IFあり ― 空白行はVLOOKUPをスキップ
=IF(A2="", "", VLOOKUP(A2, マスタ!D:E, 2, FALSE))

A2が空白の場合、IFの短絡評価により
空白行では検索結果を求めない形にできる。
空白行が多いブックでは比較候補になる。
設計上の目安個別セル式での使い方
=IF(A2="", "", VLOOKUP(...)) は、空白行では検索結果を必要としないことを明示できます。関数・配列・Excel版によって評価方法の詳細は異なる可能性があるため、「計算コストがゼロ」とは断定せず、変更前後を計測します。
スピル式：事前IFだけで決めない

スピル式で同じIFチェックを行った場合の効果は、配列サイズ、検索関数、Excelの版で変わるため実測します。

比較案A：スピルの事前IF
=IF(A1:A15000="", "", XLOOKUP(A1:A15000, マスタ!D:D, マスタ!E:E, "", 0))

IF条件とXLOOKUPの両方が配列を扱う構成。
結果は分かりやすい一方、事前IFだけで入力配列の大きさは変わらない。
比較案B：if_not_foundを使う
=XLOOKUP(A1:A15000, マスタ!D:D, マスタ!E:E, "", 0)

第4引数 if_not_found に "" を指定。
空白検索値がマスタに該当しなければ自動で""を返す。
事前IFが不要なら、式を短くできる。
🔴 配列IFの内部評価を一般化しない
コミュニティ検証では分岐の両側が評価されたように見える例がありますが、1つの式から「すべての配列IFが常に両分岐を全計算する」とは断定できません。本記事では、入力配列を実データ範囲に絞る案と、事前IFを使う案を実測比較します。
事前IF空白チェックの効果 ― 比較まとめ
方式IFの評価空白行のVLOOKUP速度効果
個別セル数式 + 事前IF 短絡評価あり スキップされる 負荷を抑える候補
スピル式 + 事前IF 配列式のため要実測 入力配列の範囲に依存 効果は式と版による
スピル式 + if_not_found="" IF不使用 入力配列の範囲に依存 式を短くできる
スピル式 + 最終行カウント IF不使用 空白行が範囲外 入力範囲を絞る候補
✅ 結論
・個別セル数式（非スピル）を使う場合 → =IF(A2="","", VLOOKUP(...)) は、空白行が多いほど負荷を抑えやすい。
・スピル式を使う場合 → 事前IFだけでは効果が出にくいため、最終行を求めて範囲を絞る方法を検討します。

【7】最終行カウント ― スピル式の参照範囲を絞る

スピル式の負荷を見直す基本は、事前IFだけに頼らず、 入力配列のサイズ自体を最小化することです。 空白行をIFでスキップするのではなく、そもそも空白行を含まない範囲だけを渡します。

基本形：COUNTAで最終行を取得してスピル範囲を絞る
❌ 固定範囲 ― 空白行も含む
=XLOOKUP(A1:A15000, マスタ!D:D, マスタ!E:E, "", 0)

データが8,000行でも、数式上の入力配列はA1:A15000。
実データより広い範囲を渡す構成になる。
✅ 最終行カウント ― データ行だけを処理
=XLOOKUP(A1:INDEX(A:A, COUNTA(A:A)), マスタ!D:D, マスタ!E:E, "", 0)

COUNTA(A:A) が8,000を返す前提なら、数式上の入力範囲をA1:A8000にできる。
途中空白、数式で返した空文字、ヘッダーの有無に注意する。
設計上の目安入力範囲を管理する理由
① 数式が参照する配列を実データに近づけられる。
② 最終行の判定を1か所にまとめ、複数の式で再利用できる。
③ 事前IFが必要かどうかを、データの途中空白と出力要件から判断しやすい。
実際の再計算時間は対象ブックで確認してください。
LETとの組み合わせ（推奨形）

LETで最終行計算を変数化することで、可読性が高く保守しやすい数式になります。

✅ 推奨：LET + COUNTA + XLOOKUP
=LET(
  最終行, COUNTA(A:A),
  検索値, A1:INDEX(A:A, 最終行),
  XLOOKUP(検索値, マスタ!D:D, マスタ!E:E, "", 0)
)

COUNTAの計算が1回だけ変数に格納され、INDEX で範囲を動的に構成。
スピル配列のサイズが実データ行に自動調整される。
途中に空白がある場合の対策

COUNTA はセルに値があるものをカウントするため、 データの途中に空白セルがあるとカウントがずれます。 途中に空白を含む可能性がある場合は、最終データ行を正確に取得する方法を使います。

数値データの場合
=LET(
  最終行, MATCH(1E+99, A:A, 1),
  検索値, A1:INDEX(A:A, 最終行),
  XLOOKUP(検索値, マスタ!D:D, マスタ!E:E, "", 0)
)

MATCHの近似一致(型1)を使う方法。
昇順など近似一致の前提を満たす数値列でのみ使用する。
文字列・数値混在の場合
=LET(
  最終行, MAX((A:A<>"")*ROW(A:A)),
  検索値, A1:INDEX(A:A, 最終行),
  XLOOKUP(検索値, マスタ!D:D, マスタ!E:E, "", 0)
)

空でないセルのROW番号の最大値を取得。
空でないセルの最大行を求める例。列全体の配列計算になるため、限定範囲でも比較する。
⚠️ MAX配列計算のコスト
MAX((A:A<>"")*ROW(A:A)) は列全体に対する配列演算で、それ自体にもコストがあります。 データに途中空白がないことが保証されているなら COUNTA の方が軽量です。
途中空白がある場合は、テーブル参照や限定範囲を使う方法も比較してください。
