バッチファイルでフォルダ内のCSV・テキストを1つに結合する

毎月のCSVや分割されたテキストファイルを、コピー＆貼り付けせずに1つにまとめます。よく紹介される copy コマンドの落とし穴と、見出しを1行だけ残すバッチファイルの作り方を、実機で確認した結果とともに説明します。

目次（7項目）
  1. どの方法を使うか
  2. copyコマンドの落とし穴
  3. 見出しを1行だけ残すバッチファイル
  4. テキストファイルをつなぐだけのとき
  5. 結合の順番
  6. うまくいかないとき
  7. 結合後の確認

1. どの方法を使うか

毎月届くCSVや、分割されたテキストファイルを1つにまとめる方法はいくつかあります。結合だけなら、バッチファイルが手軽です。整形や集計まで続けるなら、Power Queryが向いています。

結合の方法の比較
方法向いている場面注意点
copy /b の1行見出しのないファイルを、その場でつなぐ見出しが重複する。最後に改行がないと行がつながる
バッチファイル（この記事）見出しが同じCSVを、毎回同じ手順で1つにするシフトJIS向け。整形はできない
Power Queryのフォルダー取り込みUTF-8のCSV、ファイル名の列がほしい、整形や集計まで行うExcelの中で作業する
💡 VBAではありませんが、実行前に確認を
バッチファイルはVBAやマクロではありません。ただし、職場によってはバッチファイルやコマンド プロンプトの実行が制限されています。社内ルールに従ってください。実行できないときは、設定を変更して回避せず、Power Queryの方法を使ってください。

2. copyコマンドの落とし穴

よく紹介される方法は、コマンド1行です。対象のフォルダーを開き、アドレスバーに cmd と入力して Enter を押すと、そのフォルダーでコマンド プロンプトが開きます。

mkdir output copy /b *.csv output\merged.csv

見出しのないファイルなら、これで足ります。ただし、次のような落とし穴があります。いずれも検証で確認しました。

copy コマンドの落とし穴
状況起きること
見出しのあるCSV見出しがファイルの数だけ途中に入る
最後に改行がないファイル次のファイルの1行目とつながる（例：2026/5/1,田中,300日付,担当,金額）
/b を付けない結果の末尾に制御文字（0x1A）が入る
BOM付きUTF-8のファイルBOMがファイルの数だけ途中に入る

行がつながると、Excelで開いたときに列がずれたり、データが1行消えたように見えたりします。件数の確認が大切です。

3. 見出しを1行だけ残すバッチファイル

次のバッチファイルは、見出しを先頭の1行だけ残し、改行のないファイルがあっても行がつながらないようにします。元のCSVは変更しません。

@echo off chcp 932 >nul setlocal cd /d "%~dp0" rem 設定（ここを実際の内容に合わせて変えます） set "HEADER=日付,担当,金額" set "OUT=output\結合結果.csv" set "WORK=output\作業用.tmp" if not exist output mkdir output if exist "%WORK%" del "%WORK%" rem CSVを順につなぐ（最後に改行がないファイルに備えて、1行足す） for %%F in (*.csv) do ( type "%%F" >> "%WORK%" echo(>> "%WORK%" ) rem 見出しを1行だけ残し、残りの見出しと空行を除く > "%OUT%" echo %HEADER% findstr /v /b /c:"%HEADER%" "%WORK%" | findstr /v "^$" >> "%OUT%" del "%WORK%" echo 完了しました。結果: %OUT% pause

作り方

  1. 結合したいCSVを、専用のフォルダーにコピーします。
  2. メモ帳を開き、上のコードを貼り付けます。
  3. HEADER= の後ろを、CSVの1行目とまったく同じ文字に書き換えます。
  4. 「名前を付けて保存」で、ファイル名を 結合.bat、ファイルの種類を「すべてのファイル」、エンコードを ANSI にして、CSVと同じフォルダーに保存します。保存後、メモ帳の右下に「Windows (CRLF)」と「ANSI」と表示されていることを確認します。
  5. 結合.bat をダブルクリックします。
  6. output フォルダーの 結合結果.csv を確認します。
⚠️ エンコードはANSIで保存します
メモ帳の既定はUTF-8です。UTF-8のまま保存すると、検証ではファイル名が文字化けし、見出しも正しく書き込まれませんでした。改行が「Unix (LF)」の場合は、結果がまったく出力されませんでした。

処理の流れ

バッチファイルの処理
行役割
chcp 932シフトJISとして読み書きする
cd /d "%~dp0"バッチファイルのあるフォルダーで処理する
type と echo(ファイルを順につなぎ、ファイルごとに改行を足す
> "%OUT%" echo %HEADER%結果の1行目に見出しを書く
findstr /v /b /c:"…"見出しで始まる行を除く
findstr /v "^$"空行を除く
del "%WORK%"作業用ファイルだけを消す（元のCSVは消さない）

結果は output フォルダーに出すので、もう一度実行しても、前回の結果を読み込むことはありません。

4. テキストファイルをつなぐだけのとき

見出しのないテキストファイルなら、見出しの処理を省きます。空行は取り除かれます。

@echo off chcp 932 >nul setlocal cd /d "%~dp0" set "OUT=output\結合結果.txt" set "WORK=output\作業用.tmp" if not exist output mkdir output if exist "%WORK%" del "%WORK%" for %%F in (*.txt) do ( type "%%F" >> "%WORK%" echo(>> "%WORK%" ) findstr /v "^$" "%WORK%" > "%OUT%" del "%WORK%" echo 完了しました。結果: %OUT% pause

5. 結合の順番

検証では、ファイル名の文字順につながりました。数値の大きさの順ではないので、桁数をそろえます。

ファイル名と結合の順番
ファイル名結合された順番
1.txt, 2.txt, 10.txt1 → 10 → 2
売上_3月.txt, 売上_12月.txt売上_12月 → 売上_3月
売上_2026-03.txt, 売上_2026-12.txt売上_2026-03 → 売上_2026-12（おすすめ）

順番が重要なときは、結合後にExcelで並べ替えて確認します。ネットワーク上のフォルダーなど、環境によって順番が変わるかどうかは確認していません。

6. うまくいかないとき

よくある症状と対処
症状原因対処
見出しが途中に残るHEADER と1行目が違う（「担当」と「担当者」など）列の構成が違う可能性があります。ファイルを確認して、列をそろえます。
見出しが文字化けする／全部の見出しが残るデータがUTF-8、またはバッチファイルの保存形式が違うこの記事のバッチファイルはシフトJIS向けです。UTF-8のCSVはPower Queryを使います。
結果のファイルができない改行が「Unix (LF)」で保存されているメモ帳の右下を確認し、「Windows (CRLF)」にして保存し直します。
空行が消えたfindstr /v "^$" で除いている空行に意味があるデータには使いません。
結果を開くと先頭のゼロが消えるExcelで直接開いた「テキストまたはCSVから」で取り込みます。
どのファイルの行か分からないファイル名を列に入れていないPower Queryの「Source.Name」列を使います。

文字コードが混ざるとき

シフトJISとUTF-8のファイルを同じバッチファイルで結合しないでください。バッチファイルは文字コードを変換しないので、結果の一部が文字化けします。

記事で使わなかった方法

見出しを除く方法としてよく紹介されるものの、検証で問題があったので、この記事では使っていません。

使わなかった方法
方法検証で起きたこと
more +17万行のファイルで30秒たっても終わらなかった。タブが空白に変わった
for /f で1行ずつ出力空行と、; で始まる行が消えた

7. 結合後の確認

  1. 行数：元のファイルの行数の合計から、ファイル数を引き（見出しの分）、1を足した数と一致するか確認します。
  2. 見出し：2行目以降に見出しが残っていないか、Excelのフィルターで確認します。
  3. 文字化け：日本語の列を確認します。
  4. つながった行：列の数が多い行がないか確認します。
