Word差し込み印刷で郵便番号と日付を整える方法

💡 やりたいこと

Wordの差し込み印刷でExcel住所録を使ったとき、郵便番号が 1000001 や 0010001 のようにハイフンなしで表示されることがあります。

日付も、Excelでは「2026年7月4日」と見えているのに、Wordでは 7/4/2026 と表示されることがあります。郵便番号と日付のどちらも、Excel側に完成済みの印刷用列を作る方法と、Word側で整える方法があります。

結論：一般の担当者が使うならExcelの印刷用列が分かりやすいです。
郵便番号は =TEXT(C2,"000-0000")、日付は =TEXT(D2,"yyyy年m月d日") で表示を完成させ、Wordではその列を差し込みます。共有住所録へ列を追加できない場合は、Word側のフィールドコードを使います。

一般的にはどう対応していることが多いか

郵便番号のハイフン問題は、Wordだけの問題というより、Excel住所録の持ち方 と Word差し込み印刷の表示方法 が混ざって起きることが多いです。現場では、だいたい次のどれかで対応されています。

よくある対応方法
対応方法 よくある理由 注意点
Excel側に作業列を作る =TEXT(A2,"000-0000") や =LEFT(TEXT(A2,"0000000"),3)&"-"&RIGHT(TEXT(A2,"0000000"),4) で、ハイフン付き列を作ってから差し込む。 一番分かりやすい反面、住所録に印刷用の列が増えます。共有ファイルやCSV貼り替え運用では表が崩れやすくなります。
Excelの表示形式だけ変える 郵便番号列にユーザー定義の表示形式 000-0000 を設定する。 Excel上ではきれいに見えても、Word差し込み印刷では表示形式がそのまま反映されないことがあります。

Wordの差し込み印刷は「差し込みフィールドを入れる」操作までは知られていても、Alt + F9 でフィールドコードを開き、\# で表示形式を指定するところまではあまり共有されていないことが多いです。そのため、Excel側に作業列を作って解決しようとする流れになりがちです。

方法1：ExcelのTEXT関数で郵便番号と日付の印刷用列を作る

C列にハイフンなしの郵便番号、D列に日付が入っている場合は、別列に次の式を入れます。

=TEXT(C2,"000-0000") =TEXT(D2,"yyyy年m月d日")
TEXT関数で作る印刷用列
元の値印刷用列の式結果
郵便番号 4702531=TEXT(C2,"000-0000")470-2531
日付 2026/7/4
内部値 46207		=TEXT(D2,"yyyy年m月d日")2026年7月4日

列名を「郵便番号_印刷用」「日付_印刷用」とし、Wordでは元の列ではなく印刷用列を差し込みます。郵便番号はハイフン付き、日付は年月日の文字列として完成しているため、Word側で別の形式へ変わりにくくなります。

日付を直接差し込むと 7/4/2026 になることがあります。
2026年7月4日はExcel内部では日付シリアル値 46207 です。Wordがこの値を日付として受け取り、自分の既定形式で再表示すると、画像のような 7/4/2026 になります。データが壊れたのではなく、同じ日付の表示形式が変わった状態です。
後工程の人が迷いにくい方法です。
表示がExcel側で完成しているため、Wordでは通常の差し込みフィールドを挿入するだけです。Alt + F9 や表示形式スイッチを覚える必要がありません。
元の郵便番号列と日付列は残してください。
TEXT関数の結果は文字列です。日付の並び替え、検索、期間計算には元の日付シリアル値を使います。また、郵便番号の式はハイフンなしの7桁数値を想定しているため、ハイフン付き文字列や全角数字が混ざる住所録は先に入力形式を統一します。

方法2：郵便番号をWordのフィールドコードで整える

共有住所録へ列を追加できない場合は、Excelの元データを変えず、Word側で表示形式を指定します。この方法は正攻法ですが、操作はWord中級者向けです。

Wordの差し込み印刷を使う人でも、多くは次の操作範囲で止まります。

  • Excel住所録を選ぶ。
  • 「差し込みフィールドの挿入」で氏名・住所・郵便番号を入れる。
  • 「結果のプレビュー」で表示を確認する。
  • 封筒、ラベル、案内文書を印刷する。

一方で、次の操作まで知っている人はかなり少数派です。

  • Alt + F9 で差し込みフィールドの中身を見る。
  • Ctrl + F9 でフィールド用の波かっこを作る。
  • \# "000'-'0000" のような表示形式スイッチを書く。
  • 手入力の { } ではフィールドとして動かないことを知っている。
つまり、機能としては正攻法、操作としては中級者向けです。
ExcelやAccessなどのデータソースから差し込むと、Excel側で見えている表示形式がWord側でそのまま保持されないことがあります。その場合、Word側のMERGEFIELDに表示形式スイッチ \# を指定して整える、という考え方になります。

まず答え：使うフィールドコード

郵便番号の列名が 郵便番号 の場合、Word側で次のフィールドコードを使います。

{ MERGEFIELD 郵便番号 \# "000'-'0000" }

これで、Excel側の値が 1000001 なら 100-0001、0010001 なら 001-0001 と表示できます。

おすすめは "000'-'0000" の形です。
ハイフンを '-' として文字扱いにするため、単なる表示形式の記号ではなく「ここにハイフンを出す」と明示できます。
Excel側が文字列でも、半角数字だけならこの方法で対応しやすいです。
たとえばセルの値が文字列の 1000001 や 0010001 でも、Word側のMERGEFIELDで 000-0000 形式に整えます。ただし、全角数字、余分なスペース、すでにハイフンが入っている値が混ざる場合は、後述の注意点を確認してください。

この方法の何が便利なのか

便利な点は、単に「ハイフンが入る」ことだけではありません。Excel住所録を印刷用に改造しなくて済むことが一番大きいです。

Word側で整形するメリット
便利な点 現場で効く理由
住所録をそのまま使える Excel側は 1000001 のまま。印刷用の 100-0001 列を追加しないので、元データの表構造が変わりません。
CSVや基幹データの貼り替えに強い 毎月住所録を入れ替える運用でも、Wordテンプレート側の設定は残ります。Excel側の作業列数式をコピーし直す手間がありません。
他の集計や参照を壊しにくい 列を増やさないため、VLOOKUPの列番号、Power Queryの列名、他部署の集計表がずれるリスクを減らせます。
出力先ごとに見た目を変えられる 住所録は同じまま、封筒用Wordではハイフン付き、管理用一覧ではハイフンなし、というように出力側で表示を分けられます。
先頭ゼロを表示で補える 10001 のように先頭ゼロが落ちている値でも、Word上では 001-0001 と表示できます。
つまり、Excelは「データ」、Wordは「印刷の見た目」と役割分担できます。
住所録をきれいに保ったまま、差し込み印刷だけ郵便番号をハイフン付きにできるので、共有ファイルや定期更新のある現場ほど効果が大きい方法です。

Excel側に作業列を作らない方がよいケース

Excel側の印刷用列は分かりやすい方法ですが、共有住所録の列構成を変更できない場合や、CSVを毎回そのまま差し替える場合はWord側で整える方が向いています。

Excel側で作業列を作る場合の問題
問題 現場で起きやすいこと
表の形が変わる 列が1本増えることで、他の人が使っている参照範囲、列番号、Power Query、集計表がずれることがあります。
元データと出力用データが混ざる 住所録の中に「印刷のためだけの列」が増え、どれが正式な郵便番号なのか分かりにくくなります。
更新時に壊れやすい CSVや基幹システムから貼り替えるたびに、作業列の数式が消えたり、範囲外になったりします。
先頭ゼロの扱いで事故りやすい 0010001 のような値がExcel側で数値として扱われると 10001 になり、見た目だけ直しても原因が見えにくくなります。
変更できない元データにはWord側の方法が有効です。
印刷用列を安全に追加・維持できる住所録ならExcel側、列構成を固定したい共有データならWord側、と使い分けます。

フィールドコードの意味

フィールドコードの分解
部分 意味
{ MERGEFIELD 郵便番号 } Excel住所録の「郵便番号」列を呼び出します。
\# "000'-'0000" MERGEFIELDに指定する表示形式です。7桁の郵便番号として、3桁目と4桁目の間にハイフンを表示します。

000 は前半3桁、'-' は文字としてのハイフン、0000 は後半4桁です。桁数が足りない場合も、先頭にゼロを補って表示できます。

フィールドコードの設定手順

ここが一番つまずきやすいところです。Wordのフィールドコードの { } は、キーボードで普通に入力した波かっこでは動きません。「差し込みフィールドの挿入」または Ctrl + F9 でWordに作らせます。

手入力の { } はNGです。
見た目が同じでも、Word内部では「ただの文字」と「フィールド」は別物です。フィールドとして動かすには、Wordにフィールドを挿入させる必要があります。

手順1：郵便番号を表示したい場所にカーソルを置く

差し込み印刷文書を開き、封筒や宛名ラベルの郵便番号を表示したい位置をクリックします。

手順2：郵便番号の差し込みフィールドを挿入する

「差し込みフィールドの挿入」から 郵便番号 を入れます。

{ MERGEFIELD 郵便番号 }

手順3：表示形式スイッチを追加する

Alt + F9 でフィールドコード表示に切り替え、郵便番号 の後ろに表示形式スイッチを追加します。

{ MERGEFIELD 郵便番号 \# "000'-'0000" }

手順4：フィールドを更新して表示を確認する

フィールド全体を選択し、F9 を押して更新します。差し込み結果のプレビューで、1000001 が 100-0001 のように表示されるか確認します。

表示の切り替え：
フィールドコードの表示／非表示は Alt + F9 で切り替えます。コードが見えている状態と、実際の表示結果が見えている状態を行き来できます。
波かっこはWordに作らせます。
画面上では同じ { } に見えても、手入力した波かっこはフィールドとして動きません。必ず「差し込みフィールドの挿入」または Ctrl + F9 で作ったフィールドを使います。

100-0001 100-0001 すでにハイフン付きなら、この表示形式は使わず通常の { MERGEFIELD 郵便番号 } で差し込みます。

列名が違う場合

Excel側の列名が 郵便番号 ではない場合は、MERGEFIELDの名前も合わせます。

{ MERGEFIELD 〒 \# "000'-'0000" } { MERGEFIELD 郵便番号1 \# "000'-'0000" } { MERGEFIELD zip \# "000'-'0000" }

列名にスペースや記号があると扱いにくいことがあります。差し込み印刷で使う列名は、できれば短く分かりやすい名前にしておくと安全です。

うまく表示されない時の確認ポイント

  • 波かっこを手入力していないか：「差し込みフィールドの挿入」または Ctrl + F9 でフィールドを作ります。
  • フィールド名がExcelの列名と一致しているか：郵便番号、〒、郵便番号1 などを確認します。
  • フィールドを更新したか：対象フィールドを選択して F9 を押します。
  • コード表示のままになっていないか：Alt + F9 で表示を切り替えます。
  • Excel側にハイフンがすでに入っていないか：ハイフン入りデータにはこの表示形式を使いません。
  • 全角数字や余分なスペースが混ざっていないか：Wordの表示形式だけでは直しにくいので、元データの品質として確認します。

まとめ

一般担当者が使うなら、Excel側に郵便番号と日付の印刷用列を作る方法が分かりやすく、Wordでフィールドコードを編集する必要がありません。

=TEXT(C2,"000-0000") =TEXT(D2,"yyyy年m月d日")

共有住所録へ列を追加できない場合、郵便番号はWord側で次のフィールドコードを使えます。日付のフィールドコードは関連記事で詳しく解説しています。

{ MERGEFIELD 郵便番号 \# "000'-'0000" }

どちらも 1000001 を 100-0001、0010001 を 001-0001 と表示できます。利用者のスキルと住所録の管理方法に合わせて選びます。
