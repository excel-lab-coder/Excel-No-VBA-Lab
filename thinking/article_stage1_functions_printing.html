段階1：VLOOKUP、印刷、データ整形でExcelの便利さに気づく時期

Excelの成長は、最初からVBAやPower Queryに行くわけではありません。多くの場合、最初の転機はVLOOKUP、IFERROR、MID、印刷設定、差し込み印刷あたりです。

入社して1年から3年くらい経つと、日々の入力作業だけでなく、既存の表を少し楽に扱う方法に気づき始めます。ここでExcelは、単なる「入力する表」から「仕事を少し動かせる道具」に変わります。

この段階は地味です。まだ自動化という言葉は出てきません。けれど、実務ではかなり大きい。なぜなら、ここで初めて「人が探す」「人が直す」「人が整える」という作業を、関数や印刷設定に少しずつ任せられるようになるからです。

この記事で扱う流れ

  2. VLOOKUPで表同士がつながる
  3. 印刷と差し込み印刷で実務の形になる

  5. INDEX + MATCHで一段上に行く
  6. この段階でできるようになること

この段階で起きる変化

最初はセルに文字や数字を入れるだけだったExcelが、検索、置換、整形、印刷、集計を助ける道具に見え始めます。ここで一度、仕事の見え方が変わります。

たとえば、今まではマスタ表を開いて、目で商品名を探して、別の表に転記していた。担当者名も部署名も、都度コピーしていた。印刷も、毎回改ページを直していた。こういう作業が、関数や設定で少しずつ消えます。

この変化は小さく見えますが、本人の中ではかなり大きいです。「Excelは入力されたものを保存する場所」ではなく、「入力されたものから結果を作る場所」だと分かり始めるからです。

段階1の本質

作業を完全に自動化する段階ではありません。手作業の中にある検索、確認、転記、整形、印刷調整を、少しずつExcelへ渡していく段階です。

最初に効くのはVLOOKUP

多くの人にとって、最初の衝撃はVLOOKUPです。コードを入力すると商品名が返る。社員番号を入力すると氏名や部署が返る。手で探していたものが、自動で引けるようになる。

この段階で、Excelが「表を作る道具」ではなく「表同士をつなぐ道具」だと分かります。これはかなり大きい発見です。入力表、商品マスタ、社員マスタ、単価表、部署一覧。それぞれ別々だった表が、キーを通してつながります。

最初は、VLOOKUPの列番号を数えるだけでも大変です。検索値が左端にないと動かない、完全一致にしないと危ない、列を挿入すると結果がズレる。こういうつまずきも含めて、表の構造を意識し始めます。

=VLOOKUP(A2, 商品マスタ!A:D, 3, FALSE)

この1本の式で、手で探していた情報が返る。初めて見ると、本当に少し世界が変わります。

この時期の代表スキル

VLOOKUP、IF、COUNTIF、SUMIF、IFERROR、LEFT / MID / RIGHT、TEXT、表示形式、フィルター、並べ替え、ピボットテーブルの入口。

印刷と差し込み印刷で、実務感が一気に出る

関数と同じくらい大きいのが、印刷設定です。印刷範囲、改ページ、ヘッダー、余白、拡大縮小。これを理解すると、Excelは画面上の表ではなく、帳票や配布物を作る道具になります。

現場では「画面上で正しい」だけでは足りません。きれいに1ページに収まる。部署ごとにページが分かれる。提出先が見やすい。印刷したときに罫線や見出しが崩れない。ここまでできて、初めて実務で使えるExcelになります。

さらにWordの差し込み印刷まで使えるようになると、宛名ラベル、案内文、封筒、一覧表の作成が一気に楽になります。Excelをデータベースとして使い、Wordを出力先として使う。ここで、Excelが他のOfficeアプリとつながる感覚も少し出てきます。

この時点で、単なる入力担当から「この人に頼むと配布物や帳票が早い」という立ち位置に変わります。一般事務の現場では、このあたりまで安定して使えるだけでもかなり頼られる側になります。

MIDやIFERRORに触れると、データの汚れが見えてくる

次に出てくるのが、文字列の整形です。商品コードの先頭だけ取りたい。固定長の文字列から日付だけ抜きたい。住所から都道府県だけ分けたい。CSVから取り込んだ値の前後に空白が混じっている。

ここでLEFT、MID、RIGHT、FIND、SUBSTITUTE、TRIMなどに触れます。最初は「文字を切り出す関数」として覚えますが、実務で使っているうちに、データは最初からきれいではないと気づきます。

IFERRORもこの時期に効きます。VLOOKUPで見つからないとエラーになる。文字列の位置が見つからないとエラーになる。割り算で0除算になる。こうしたエラーをどう見せるか、どう止めるかを考え始めると、Excelは少しだけ設計に近づきます。

=IFERROR(VLOOKUP(A2, 商品マスタ!A:D, 3, FALSE), "未登録")

エラーを消すこと自体が目的ではありません。未登録なのか、入力ミスなのか、マスタ不足なのか。原因が分かる形で見せることが大事になります。このあたりから、関数は単なる便利技ではなく、運用を支える部品になっていきます。

INDEX + MATCHに触れると、少し上の世界が見える

VLOOKUPの「左側を検索できない」「列番号がズレると壊れる」という弱点に気づくと、INDEX + MATCHに進みます。ここに来ると、かなりExcelができる人の雰囲気が出てきます。

INDEXは範囲の中から指定位置の値を返す。MATCHは値が何番目にあるかを返す。2つを組み合わせると、列番号を固定で数えなくても、検索結果を取り出せます。

=INDEX(商品マスタ!C:C, MATCH(A2, 商品マスタ!A:A, 0))

この式を理解すると、Excelの見え方が変わります。VLOOKUPのように1つの関数を覚える段階から、「部品を組み合わせて目的の結果を作る」段階に入るからです。

ここでさらに、MATCHで行番号を取り、別のMATCHで列番号を取り、INDEXで交差点を返すような考え方に進む人もいます。ここまで来ると、もう単なる表作成ではなく、小さな検索システムを作っている感覚に近くなります。

この段階でできるようになること

段階1は、まだ自動化の段階ではありません。それでも、実務でははっきり景色が変わります。入力された値をそのまま並べる人から、データを探し、整え、帳票として出せる人へ変わるからです。

この時期にできるようになることは、次の段階の土台になります。VBAに進む人も、Power Queryに進む人も、まずここで「表は構造を持っている」「キーがあれば表はつながる」「データは汚れている」「画面で正しいだけでは実務にならない」という感覚を身につけます。

ただし、ここに到達しても、最初から関数を組み合わせて最適化できるわけではありません。VLOOKUPやINDEX + MATCHの研修を受けても、自力で実務の式を完成できないことは普通にあります。それでも無駄ではありません。大きいのは、「これは検索関数で対処できそうだ」「マスタやキーを見れば何か分かりそうだ」と気づけることです。

できるようになること 最初に起きる変化 取れる対応
VLOOKUPやINDEX + MATCHで検索する 目視転記を減らす以前に、表はキーでつなげられると気づく 詳しい人に「このキーでマスタ参照できますか」と聞ける。検索語も具体化できる
IFERRORで例外を扱う エラーを単なる失敗ではなく、未登録や入力ミスのサインとして見られる 原因を切り分け、マスタ不足なのか入力ミスなのかを相談できる
LEFT / MID / RIGHTで文字列を整える データはそのまま使えないことがあると分かる 桁数、区切り、空白、コード体系という観点で調べられる
印刷範囲や差し込み印刷を整える 画面上の表と、提出・配布する帳票は別物だと分かる 入力データと出力レイアウトを分けて相談できる

ここで画期的なのは、Excelが「入力したものを保存する場所」から、「入力されたものを別の形に変換する場所」へ変わることです。この感覚がないままVBAへ進むと、操作だけを記録してしまい、表の構造を見落としやすくなります。

できなくても、相談の精度が上がる

関数を完璧に書けなくても、「何を聞けばよいか」が分かるだけで仕事は変わります。組織全体でも、周囲がこの言葉を持っていると、少数のハイスキルな人へ依頼をつなぎやすくなり、評価や改善の精度も上がります。

どれぐらいの人ができるか

この段階の難しさは、資格や肩書きでは測りにくいです。VLOOKUPを知っている人はいても、業務に合わせて安全に組める人は一気に減ります。INDEX + MATCH、MID、IFERROR、印刷設定、差し込み印刷まで一通り使える人となると、一般事務の中ではかなり少数派です。

もちろん職場によって差はあります。Excelが強い部署なら珍しくないかもしれません。一方で、紙中心、基幹システム中心、入力作業中心の部署では、部署内に1人いるだけでかなり頼られることもあります。

体感としては、SUMや罫線までなら多くの人ができます。VLOOKUPを実務で安定して使える人になると一段減り、INDEX + MATCH、文字列整形、差し込み印刷まで自然に組み合わせられる人はさらに少なくなります。

状態 できること 現場での見え方
基本操作中心 入力、罫線、簡単な合計、並べ替え 普通にExcelを使える人
VLOOKUPまで使える マスタ参照、転記削減、確認作業の短縮 Excelが得意な人
INDEX + MATCHや文字列整形まで使える 表構造に合わせた検索、データ整形、エラー制御 困ったときに呼ばれる人
印刷・差し込みまで安定 帳票、ラベル、案内文、配布物の効率化 実務を任せられる人

ここで大事なのは、珍しさそのものではありません。この段階まで来ると、Excelを「自分の作業を早くする道具」としてではなく、「部署の作業を少し楽にする道具」として使い始めることです。

手作業の限界と「人が表を管理する」ことの絶望

VLOOKUPや印刷設定を覚えたことで、作業は劇的に早くなりました。しかし、次第に「自分の手足がExcelの計算の奴隷になっている」という感覚に陥ります。

数式を下までコピーする。データが増えるたびに範囲を広げる。誰かが行を挿入して参照がズレたら直す。作業列が増えすぎて、どの列が何をしているのか分からなくなる。十分便利になったはずなのに、「人が表の機嫌を取りながら管理している」状態からは抜け出せていないのです。

処理そのものを自動で流す、ボタン1つで毎月の面倒な作業を終わらせる、という発想にはまだ届きません。この段階のExcelは「作った本人の属人的な頑張り」に依存しやすく、便利になればなるほど、保守する本人の負担が増大していくという矛盾を抱えます。

段階1の限界：セル単位の思考

数式をセルに敷き詰め、人が範囲を管理する限り、「毎月同じ手順を繰り返す作業」を丸ごと消し去ることはできません。この見えない限界が立ちはだかります。

この「自分が手を動かさないとExcelが動かない」という壁にぶつかったとき、次の段階であるVBA（マクロ）の強烈な魅力に引き込まれます。関数で結果を出すだけの世界から、「処理を自律的に動かす世界」への扉が開くのです。
