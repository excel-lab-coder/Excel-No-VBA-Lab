VBAでWebデータ取得 ― 静的ページ・API・動的画面を混同しない

「URLへアクセスできる」ことと「ブラウザに表示された内容を取得できる」ことは同じではありません。最初にページの種類を判定すると、古いIE制御や不安定な画面操作へ迷い込みにくくなります。

実務利用の前提

取得先の利用規約、robots.txt、著作権、個人情報、アクセス頻度、社内規程を確認してください。ログイン回避、CAPTCHA回避、アクセス制限の迂回を扱う記事ではありません。業務システムでは、まず公式APIや正規のエクスポート機能を確認します。

1. 先に「何を取得するか」を分ける

対象基本的な候補注意点
公開CSV・JSON・静的HTMLPower Query / HTTP要求JavaScriptは実行されない
Excelへ定期取込まずPower Query更新手順を共有しやすい
JavaScript実行後の画面公式API / 承認済みブラウザ自動化VBAのHTTP要求だけでは画面状態を再現できない
他アプリへの入力操作UI Automation画面変更、権限差、ロック状態の影響を受ける

HTTPで返る本文に目的の値がなければ、待ち時間を増やしても値は現れません。ブラウザが後からAPIを呼び出して画面を組み立てている可能性があります。

2. 公開ページを1回だけ取得する最小例

次の例は、認証不要の公開URLをGETし、状態・Content-Type・本文の先頭部分を「Web取得」シートへ出します。参照設定を不要にするため遅延バインディングを使っています。

Option Explicit

Public Sub 公開ページを確認する()
    Const TARGET_URL As String = "https://example.com/"
    Dim http As Object
    Dim ws As Worksheet
    Dim body As String

    Set ws = ThisWorkbook.Worksheets("Web取得")
    Set http = CreateObject("MSXML2.ServerXMLHTTP.6.0")

    On Error GoTo Failed
    http.setTimeouts 5000, 5000, 10000, 10000
    http.Open "GET", TARGET_URL, False
    http.setRequestHeader "User-Agent", "Excel-No-VBA-Lab/1.0"
    http.Send

    ws.Range("A1:B4").ClearContents
    ws.Range("A1").Value = "取得日時"
    ws.Range("B1").Value = Now
    ws.Range("A2").Value = "HTTP状態"
    ws.Range("B2").Value = http.Status & " " & http.statusText
    ws.Range("A3").Value = "Content-Type"
    ws.Range("B3").Value = http.getResponseHeader("Content-Type")

    If http.Status < 200 Or http.Status >= 300 Then
        Err.Raise vbObjectError + 1000, , "HTTPエラー: " & http.Status
    End If

    body = http.responseText
    ws.Range("A4").Value = "本文（先頭32000文字）"
    ws.Range("B4").Value = Left$(body, 32000)
    Exit Sub

Failed:
    ws.Range("A6").Value = "失敗"
    ws.Range("B6").Value = Err.Number & ": " & Err.Description
End Sub
このコードが保証しないこと

文字コードの完全判定、HTML解析、JSON解析、再試行、認証、Cookie管理、ページング、大容量保存は含みません。セルは最大32,767文字のため、本文全体の保管用途にも向きません。

3. 取得できたかを3段階で確認する

  1. HTTP状態：200番台か。301/302、401/403、429、500番台を成功扱いしない。
  2. Content-Type：期待するHTML、JSON、CSVか。ログイン画面がHTMLで返っていないか。
  3. 本文：目的の項目が本当に含まれるか。画面に見えるだけで本文にない場合は動的生成を疑う。

4. 動的ページならVBAだけに固執しない

WebView2はEdgeの描画エンジンをアプリへ組み込む技術で、VBAから数行で既存Edgeを自由に操作する機能ではありません。実装・配布・Runtime・非同期処理を含む設計が必要です。WebDriver系もドライバーや組織の導入許可が必要になる場合があります。

そのため、実務では次の順が基本です。

  1. 公式APIまたはCSV出力
  2. Power Queryで取得可能か
  3. 認証不要の静的データならHTTP取得
  4. 入力操作ならUIAを限定利用
  5. 本格的な動的画面は、管理部門承認のブラウザ自動化基盤

5. 本番化する前のチェック

  • 対象URLをセルから無制限に受け取らず、許可ドメインを決める
  • パスワードやトークンをセル、コード、ログへ平文保存しない
  • 連続アクセスを避け、429応答時は停止する
  • 取得日時、URL、HTTP状態、件数をログに残す
  • サイト変更時は自動登録せず、異常として止める
  • マクロをインターネット配布せず、組織の署名・配布ルールに従う

6. 公式参照

  • Microsoft Learn: IXMLHTTPRequest
  • Microsoft Learn: ServerXMLHTTP
  • Microsoft Learn: WebView2 documentation
  • Microsoft Learn: インターネット由来のマクロの既定ブロック

まとめ

VBAによるWeb取得の基本は、万能なスクレイピングコードを作ることではなく、静的データ・API・動的画面を先に見分けることです。公開された静的データにはHTTP取得が使えますが、動的画面や認証付き業務システムでは、公式経路と管理された自動化基盤を優先します。
